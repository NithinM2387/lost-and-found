# Database Documentation

## Database Overview

The Lost & Found application uses **MongoDB** as its database and **Mongoose** as the ODM (Object Data Modeling) library.

The database stores user accounts and Lost & Found item reports.

## Database Structure

The application uses two main collections:

- `users`
- `items`

There is no direct MongoDB relationship between the collections. The `userId` field in an item stores the ID of the user who created the report.

---

## Users Collection

The `users` collection stores registered user information.

### User Fields

| Field | Type | Description |
|---|---|---|
| `_id` | ObjectId | Unique user identifier generated by MongoDB |
| `name` | String | User's name |
| `email` | String | User's email address |
| `password` | String | Hashed user password |

Passwords are hashed using **bcryptjs** before being stored in the database.

### Example User

```json
{
  "name": "Test User",
  "email": "test@example.com",
  "password": "hashed-password"
}
```

---

## Items Collection

The `items` collection stores all Lost & Found reports.

### Item Fields

| Field | Type | Description |
|---|---|---|
| `_id` | ObjectId | Unique item identifier generated by MongoDB |
| `name` | String | Name of the lost or found item |
| `category` | String | Item category |
| `description` | String | Description of the item |
| `date` | String | Date the item was lost or found |
| `location` | String | Location associated with the report |
| `image` | String | Optional image field |
| `status` | String | Lost, Found, or Claimed |
| `approvalStatus` | String | Pending, Approved, or Rejected |
| `userId` | String | ID of the user who created the report |

### Example Item

```json
{
  "name": "Black Wallet",
  "category": "Bags",
  "description": "Black leather wallet",
  "date": "2026-09-14",
  "location": "Classroom",
  "image": "",
  "status": "Lost",
  "approvalStatus": "Approved",
  "userId": "user-object-id"
}
```

---

## Item Approval Status

Each newly submitted report has an approval status of:

```text
Pending
```

The Admin reviews the report and can change it to:

```text
Approved
```

or:

```text
Rejected
```

### Approval Flow

```text
User submits report
        ↓
     Pending
      /    \
     /      \
Approved   Rejected
   ↓          ↓
Visible     Hidden
on website  from website
```

Only reports with:

```text
approvalStatus = Approved
```

are displayed on the normal Home and Browse pages.

---

## Item Status

The `status` field represents the state of the reported item.

Possible values are:

```text
Lost
Found
Claimed
```

### Status Flow

```text
Lost
 ↓
Found
 ↓
Claimed
```

Claimed items are removed from the normal Home and Browse listings but remain stored in the database.

They are displayed in the Admin dashboard under:

```text
Claimed / Closed Items
```

---

## User Ownership

Each item stores the ID of the user who created the report:

```text
userId
```

This allows the application to identify the owner of a report.

All approved active reports are available to logged-in users through Home and Browse.

The Profile page uses the user's ID to retrieve only the reports created by that user.

---

## Database Operations

### Create Item

A new Lost or Found report is stored in the `items` collection.

The report includes the logged-in user's ID and starts with a `Pending` approval status.

### Read Items

The normal item endpoint returns approved and active reports for Home and Browse.

### Read User Reports

The application uses:

```text
/api/my-items/:userId
```

to retrieve reports created by a specific user.

### Update Item

The item status can be updated to:

```text
Found
```

or:

```text
Claimed
```

The Admin can also update the approval status.

### Delete Item

The Admin can remove an item from the database when required.

---

## Matching Data

The matching system uses item information stored in the `items` collection.

The following fields are used for rule-based matching:

- Category
- Location
- Date
- Name
- Description
- Status
- Approval status

Only approved Lost and Found reports are considered for matching.

## Database Technology

### MongoDB

MongoDB is used as the primary database for storing:

- User accounts
- Lost item reports
- Found item reports
- Item status
- Admin approval status

### Mongoose

Mongoose is used to:

- Define database schemas
- Create models
- Store documents
- Query items and users
- Update item status
- Delete reports

---

## Security Considerations

- User passwords are hashed using bcryptjs.
- Database credentials are stored in environment variables.
- Real database credentials should not be committed to the project repository.
- User IDs are stored with item reports to identify the report creator.
